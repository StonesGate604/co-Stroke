# co-Stroke：另一台 Windows 电脑安装运行命令集

本文用于在另一台 Windows 电脑上克隆、同步、测试并运行 co-Stroke v4.1。

## 前提

- 已安装 Git；
- 已安装 Python 3；
- 已在 GitHub 登录有权访问 `StonesGate604/co-Stroke` 私有仓库的账号；
- 以下命令均在 PowerShell 中执行。

## 1. 克隆项目

```powershell
$projectParent = Join-Path $env:USERPROFILE "Documents\GitHub"

New-Item -ItemType Directory -Force $projectParent
Set-Location $projectParent

git clone https://github.com/StonesGate604/co-Stroke.git
Set-Location co-Stroke

git checkout master
git pull --ff-only
```

如果 GitHub 提示登录，请使用能够访问该私有仓库的 GitHub 账号完成登录。

## 2. 创建 Python 虚拟环境

```powershell
python -m venv .venv

.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch
```

检查 PyTorch 和 CUDA 状态：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print('PyTorch:', torch.__version__); print('CUDA:', torch.cuda.is_available())"
```

如果电脑有 NVIDIA 显卡但输出仍然是 `CUDA: False`，应根据该电脑的 CUDA 环境，使用 PyTorch 官方安装页面提供的命令安装对应版本，不要直接复制旧电脑的 CUDA 配置。

## 3. 自动同步 Quick, Draw! 数据和 v4.1 模型

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync_project_assets.ps1
```

这条命令会自动下载并恢复：

```text
data\quickdraw\cat.ndjson
runs\stroke-multimodal-v41-cat\checkpoint.pt
```

模型文件会进行 SHA-256 校验。如果目标文件已存在且校验值正确，脚本不会重复下载。

### 可选：同步所有正式 checkpoint

如果还需要 v3.1 和 v4.0.1：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\sync_project_assets.ps1 `
  -IncludeAllFormalCheckpoints
```

它会恢复：

```text
runs\stroke5-transformer-v3-cat\checkpoint.pt
runs\stroke-relational-v4-cat\checkpoint.pt
runs\stroke-multimodal-v41-cat\checkpoint.pt
```

## 4. 运行测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前预期结果：

```text
Ran 14 tests
OK
```

如果测试失败，先保留完整错误信息，检查 Python、PyTorch、路径和 checkpoint 是否完整，不要立即修改模型结构。

## 5. 启动网页服务

在第一个 PowerShell 终端中，进入项目根目录：

```powershell
Set-Location "$env:USERPROFILE\Documents\GitHub\co-Stroke"
.\.venv\Scripts\python.exe -m http.server 8000
```

浏览器打开：

```text
http://127.0.0.1:8000/public/
```

这个终端需要保持运行。

## 6. 启动 v4.1 模型服务

再打开一个 PowerShell 终端，进入项目根目录：

```powershell
Set-Location "$env:USERPROFILE\Documents\GitHub\co-Stroke"
```

### 有可用的 NVIDIA CUDA

```powershell
.\.venv\Scripts\python.exe scripts\serve_stroke_model.py `
  --checkpoint runs\stroke-multimodal-v41-cat\checkpoint.pt `
  --device cuda
```

### 没有 CUDA

```powershell
.\.venv\Scripts\python.exe scripts\serve_stroke_model.py `
  --checkpoint runs\stroke-multimodal-v41-cat\checkpoint.pt `
  --device cpu
```

这个终端也需要保持运行。

## 7. 检查模型服务

在第三个 PowerShell 终端中运行：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/health |
  ConvertTo-Json -Depth 5
```

确认返回内容中的模型类型为：

```text
stroke-multimodal-v4.1
```

健康检查也可以直接在浏览器中打开：

```text
http://127.0.0.1:8787/health
```

## 8. 开始使用

确认以下两个地址都能访问：

```text
网页：http://127.0.0.1:8000/public/
模型：http://127.0.0.1:8787/health
```

回到绘画网页并刷新，然后画一笔，再点击 **AI Continue**。

如果模型服务没有正常运行，前端可能退回 mock stroke。因此不能只根据按钮能够点击来判断模型已经加载，必须同时检查 `8787/health`。

```text

不要擅自修改模型结构或覆盖训练结果。完成后请报告：

2. PyTorch 和 CUDA 状态；
3. Quick, Draw! 数据文件大小；
4. checkpoint 文件大小和 SHA-256；
5. 单元测试结果；
6. 8000 端口网页状态；

```
